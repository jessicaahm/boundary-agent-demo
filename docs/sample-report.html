The root CA's total lifetime is only 180 days, very short for a root, and the issuer is set to leaf_not_after_behavior: "err": once a requested certificate would outlive the CA, Vault refuses to issue it rather than shortening it. Issuance from pki/ therefore starts failing well before April 2027.

The expired leaf was issued for test.example.com (SAN DNS:test.example.com, server and client auth) with a 60-minute lifetime, so it died an hour after issue — a test artifact, not a lapse.

Last written and rotated

Nothing with a known write date has ever been rotated — all 12 dated objects are still on their first version.

The gap is eso-sync/api and eso-sync/db. Their write dates are genuinely unavailable rather than old: KV timestamps live on Vault's metadata endpoint (<mount>/metadata/<path>, which returns created_time, updated_time and current_version), and the Vault MCP server exposes no tool that reaches it — read_secret rewrites every KV v2 path to data/ and returns only the value. vault kv metadata get eso-sync/api from the CLI returns those fields. Until then, treat those two as unknown age, not as fresh.

Two readings to keep straight. Grants scoped this + descendants at global already reach every org and project, so the three scope-level Administration roles grant admin nothing it did not already have. Observations

Six things stand out, in rough order of how much they would matter outside a demo.

  1. One identity holds everything. admin is the only real user and carries actions=* on type=* in every scope. There is no second admin and no separation of duties; the only fallback is the recovery KMS workflow.

  2. Every authenticated user can enumerate all targets. ids=*;type=target;actions=list,read at global with descendants means anyone who logs in sees every target in every scope. It stops short of connecting — no authorize-session grant — so this is enumeration, not access.

  3. The root CA expires 7 April 2027. It will stop issuing usable certificates before that date. Renewing it is the one dated action in this report; clearing the expired test leaf is housekeeping.

  4. No groups. With 0 groups and 0 managed groups, every future user needs roles assigned individually. Adding a second person is the moment to introduce a group.

  5. Three redundant roles. The scope-level Administration roles on devops, aws and kubernetes are fully covered by the global role's descendants grant. They are harmless but they make the access picture look broader than it is.

  6. Two PKI mounts look unfinished. pki2/ and pki-external-ca/ return no roles, no issuers and no certificates, while pki/ has a ROOTCA issuer and a test role. Worth confirming whether the other two are still needed.

One more, scoped to this demo: the 10 static/demo/ secrets were generated in a terminal session, so their values exist in that scrollback. Fine as demo data; regenerate them server-side if any of those paths ever stand in for something real.

Limits. Everything here is what this token is authorized to see — in Boundary, absence from a listing is not proof of nonexistence. KV write timestamps are likewise unavailable through these tools. Grants are reported as configured and are not a test that a session to any target succeeds.
